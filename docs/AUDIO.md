# 音频系统设计（一企推推乐 / Push & Fun）

> 面向：后续维护音频的人。
> 素材怎么来的、代码怎么跑的、音量为什么是这个数、验收听什么 —— 都在这份里。
> 相关文件：`js/utils/audio-cues.js`（音效表，唯一数据源）、`js/utils/audio-manager.js`（引擎）、
> `tools/gen-sfx.py`（素材生成器）、`tools/audio-lab.html`（试听台）。

---

## 1. 先看诊断：原来那套音频坏在哪

接手时的现状是 7 个 WAV + 1 条 BGM，全部由 `tools/generate-audio.html` 里几个振荡器直接倒出来。
实测（`python tools/gen-sfx.py --verify` 的同类指标）结果如下：

| 问题 | 实测证据 | 玩家的感受 |
| --- | --- | --- |
| **点按音是静音文件** | `button.wav` 4800 个采样全为 0，峰值 0.000 | 点按钮没声，以为游戏坏了 |
| **音色是"电子哔声"** | 单个振荡器 + 频率滑音，无起音包络、无尾音、无分层 | 跟冰雪 + 企鹅的美术完全脱节 |
| **采样率混乱** | 音效 48kHz，BGM 16kHz（高频砍到 8k） | 音效刺、音乐闷，像隔了一层棉被 |
| **未压缩 WAV 占体积** | 7 个短音效 + 512KB BGM = 768KB，其中 48kHz 对手机扬声器毫无收益 | 主包白白占掉 0.77MB |
| **循环有断层** | BGM 16s，收尾用 8ms 淡出到 0 再跳回开头 | 每 16 秒一次"呼吸"，听五分钟就烦 |
| **直流偏移** | `collision.wav` DC = −0.0248，`push.wav` DC = −0.0077 | 小扬声器上"噗"一声，像破音 |
| **没有并发控制** | `playSound` 每次 `stop()` 再 `play()` 同一个实例 | 连滑时上一声被硬切，"咔哒"断音 |
| **没有冷却** | 连点/连滑同一声无限叠加 | 机关枪，快速操作时特别吵 |
| **没有闪避** | BGM 与音效各自固定音量 | 通关音效和音乐糊在一起 |
| **事件覆盖不全** | 只有 7 个音效；`star.wav` 定义了但**从未被调用** | 星级亮起、成就解锁、退一步、复活全是静音 |
| **开关粒度错** | 一个"音效"按钮同时关掉音乐和音效 | 想静音音乐就得连音效一起没 |

一句话总结：**这不是"音效不好听"，是根本没有音频系统**——只有 8 个文件 + 一个播放函数。

## 2. 设计目标

1. **听感定位**：冰雪 + 糖果。冷、透、轻，但要有温度；不能是电子游戏的"哔哔"声。
2. **不打扰**：推箱子是慢节奏解谜，玩家一局会听上百次滑行音。任何音效都不能"抓耳朵"超过 300ms。
3. **反馈优先**：声音的第一职责是**告诉玩家操作生效了**，第二职责才是好听。
4. **可维护**：换素材不改代码，改参数不改素材；全部素材能从脚本重新生成。
5. **真机优先**：所有设计以"手机小喇叭 + 可能戴着耳机"为准，不做只有监听耳机才听得出的细节。

---

## 3. 音色语言（四种材质）

全部音效只用四种材质组合，形成统一的"听觉 Logo"。这是让一套音效听起来像"一个游戏"的最快办法。

| 材质 | 合成方式 | 听感 | 用在哪 |
| --- | --- | --- | --- |
| **冰晶铃** | FM 合成（调制指数快速衰减） | 起音有金属"叮"，尾音是纯正弦 | 星星、成就、通关点缀 |
| **木琴** | 基频 + 3.93 倍泛音 + 极短击打噪声 | 圆润、有木头温度 | 点按、关卡开始、通关琶音 |
| **雪沙** | 带通噪声（2~7kHz）+ 颗粒调制 | 擦冰面、雪风 | 滑行、推动、BGM 反拍 |
| **气泡** | 上滑正弦 + 二次谐波 | 圆、亮、向上 | 复活 |

**每个音效都是三层结构**，缺一层就会"平"：

```
transient（0~15ms）   body（材质主体）        tail（空间）
   触感：撞到了          是什么东西：冰/木/铃      在哪里：小房间混响
```

例：`slide` = 带通噪声上扫（body）+ 8~14Hz 颗粒调制（冰面碎屑）+ 结尾一记木琴"嗒"（transient，让移动有终点）。

## 4. 系统架构

### 4.1 信号流

```
                        ┌──────────────────────────────────────────┐
                        │  js/utils/audio-cues.js  （音效表）        │
                        │  file / bus / gain / voices / cooldown   │
                        └──────────────────┬───────────────────────┘
                                           │ 读表
  game.js 事件                             ▼
  ──────────► playCue(name, opts) ─► 冷却检查 ─► 声部池取声部 ─► volume 计算 ─► play()
  （滑动/推动/撞墙/                     │            │              │
    通关/星级/成就…）                   │            │              └─ gain × 总线增益 × 推子
                                       │            └─ round-robin，忙则扩容（有上限）
                                       └─ 长音效触发 duck()

  BGM：  setBgmState('menu'|'game'|'result')
              └─► targetBgmVolume = musicVolume × 场景档 × duckFactor
                        └─► rampBgmTo(target)  40ms 一步插值，抹掉跳变
```

### 4.2 四条基础设施

**① 总线（bus）**

只有两条：`ui`（点击类，固定 ×0.72）和 `sfx`（玩法/结算，×1.0）。
分开的理由很实际：点按音和滑行音在同一帧里出现时，如果同增益，玩家会觉得"点按钮比推冰块响"，
而推冰块才是这游戏的核心反馈。UI 恒比玩法轻一档，这条规则写在 `AudioManager.busGain` 里，不要各处微调。

> 微信的 `InnerAudioContext` 没有真正的 GainNode，总线是**在赋值 volume 时乘进去**的，
> 所以调总线增益只影响"下一次播放"，不会实时改正在播的声音。

**② 声部池（voice pool）**

每个 cue 声明 `voices`：1 = 独占（长音效，后一声打断前一声），2~3 = 允许叠住。

- 冷启动每个 cue 只预热 1 个声部（20 多个实例一起开会拖慢低端机启动）；
- 连打时若声部全忙，才按需扩容，**上限就是 `voices`**；
- 到达上限后复用第一个声部（宁可变调也不要无限开实例）。

为什么必须池化：`InnerAudioContext` 不会自己回到 0 位置，播新声音必须先 `stop()`。
原来只有一个实例，`stop()` 就等于把上一声砍断——连滑时听到的"咔哒"就是这个。

**③ 冷却（cooldown）**

同一 cue 的最小间隔。`slide 55ms` / `bump 110ms` / `tap 45ms`。
没有它，快速连点就是机关枪；有了它，超出物理可能的输入会被自然吞掉，听感反而更"重"。

**④ 闪避（ducking）**

`win` / `fail` / `achievement` / `revive` 声明了 `duck`，播放期间 BGM 压低到 35%~55%，结束后 600ms 缓回。
这是混音上"音效听得清、音乐不断"的标准做法，比直接关 BGM 体面得多。

### 4.3 BGM 的场景化

一首循环曲，三个音量档：

| 场景 | 档位 | 有效音量（相对素材 −21 dBFS RMS） |
| --- | --- | --- |
| 菜单 | 1.0 | ≈ −25.4 dBFS |
| 对局 | 0.7 | ≈ −28.5 dBFS |
| 结算 | 0.45 | ≈ −32.4 dBFS |

进关卡压低、结算再压低——玩家思考时需要安静，看结果时音效才是主角。
真要换曲时，`BgmConfig` 已经按 `{ menu: 'audio/bgm-menu.wav', ... }` 的方向留好了扩展位，
届时给 `AudioManager` 加双实例交叉淡入淡出即可（`rampBgmTo` 的插值逻辑可以复用）。

两条硬规则：

   RMS 低一点反而刚好。

## 6. BGM 设计

| 项 | 值 | 理由 |
| --- | --- | --- |
| 调性 | C 大调 | 无升降号，最"不紧张"；跟所有音效同调，叠在一起不打架 |
| 速度 | 90 BPM | 解谜节奏；120 BPM 会显得催人 |
| 长度 | 16s（6 小节） | 主包体积约束下的折中，见下方"已知限制" |
| 和声 | C–Am–F–G–Am–G | 末小节停 G，回环到 C 是自然半终止 |
| 配器 | 音乐盒旋律 + 柔铺底 + 低音 + 雪沙反拍 + 冰晶点缀 | 旋律稀疏留白，避免"琶音轰炸" |
| 采样率 | 22.05kHz | 音乐盒基频到 C6(1047Hz)，泛音到 4kHz 就够；16k 会明显发闷 |

### 无缝循环怎么做的

**不用淡出。** 淡出到 0 再跳回开头，接缝处会有一次"呼吸断层"，循环三次以上必然被听出来。

做法是把所有音符和混响尾巴**按取模写回缓冲区**（`add()` 函数里的 `% n`），
超出结尾的能量折回开头：

```
渲染 16s 内容 + 1.4s 混响尾音
     ├─ 前 16s           → 循环主体
     └─ 后 1.4s 尾音     → 加到开头的 1.4s 上（而不是切掉）
```

这样接缝处能量连续，听感是"一直在响"，不是"每 16 秒重新开始"。

## 7. 素材规格

| 项 | 音效 | BGM |
| --- | --- | --- |
| 采样率 | 32000 Hz | 22050 Hz |
| 位深 / 声道 | 16bit / 单声道 | 16bit / 单声道 |
| 格式 | WAV（PCM） | WAV（PCM） |
| 峰值 | ≤ −1 dBFS（软限幅） | ≤ −2.5 dBFS |
| 响度 | −15 ~ −20 dBFS RMS（按用途分级） | −21 dBFS RMS |
| 起音 | 2ms 淡入 | 音符自带 6ms 起音 |
| 收尾 | 10~25ms 淡出到 0 | **不淡出**（尾音折回开头） |
| 直流 | 强制高通 28Hz 滤除 | 高通 30Hz |
| 总体积 | ≈ 525KB（12 个） | ≈ 689KB |

**为什么是 WAV**：本机没有可用的 mp3/aac 编码器（无 ffmpeg、无 lame），
WAV 是当前能保证"改了脚本就能重建"的唯一格式。正式版建议转 mp3 64kbps 走 CDN 或分包，
体积能再省 80%（1.2MB → 约 250KB）。转码后只需把 `audio-cues.js` 里的 `file` 改成 `.mp3`。

**命名**：`audio/<cue 名>.wav`，全小写、短横线分词。`collision.wav` / `button.wav` 是历史遗留名，
映射关系见 `CUE_ALIASES`，新素材不要沿用。

## 8. 事件 → 音效映射（代码接入点）

| 游戏事件 | 代码位置 | 音效 |
| --- | --- | --- |
| 按钮按下 | `js/ui/button.js` `onTouchStart`（全局钩子） | `tap` |
| 移动成功一格 | `game.js` `handleSwipe` 内 `playSlideSound()` | `slide` |
| 推动冰块 | `game.js` `tryMove()` 推冰块分支 | `push` |
| 撞边界 / 冰墙 / 雪堆 / 推不动 | `game.js` `tryMove()` 两个 `playCollisionSound()` | `bump` |
| 退一步成功 | `game.js` `undoMove()` | `undo` |
| 进入关卡 | `game.js` `loadLevel()` 成功后 | `levelStart` + BGM 切 `game` 档 |
| 通关 | `game.js` `onWin()` | `win` + BGM 切 `result` 档 |
| 星星逐颗亮起 | `result-scene.js` `update()` → `onStarReveal(i)` | `star`，rate `1 + i×0.12` |
| 失败 | `game.js` `onFail()` | `fail` |
| 复活成功 | `game.js` `onReviveSuccess()` | `revive` + BGM 回 `game` 档 |
| 成就解锁（非结算） | `game.js` `flushAchievementRewards({ notify: true })` | `achievement` |
| 回主菜单 | `game.js` `backToMenu()` | BGM 切 `menu` 档 |
| 切后台 / 回前台 | `game.js` `bindLifecycle()` | `suspend()` / `resume()`（不碰实例） |

### 两条"别这么写"

- **通关那一下不要同时播 `achievement`。** `onWin()` 传的是 `flushAchievementRewards({ notify: false })`，
  成就音在结算页由 `win` 音效统一覆盖；两个上行音阶同时响 = 糊。
- **星级音不要用 `slide`。** 星星是奖励音，滑行是动作音，音色混用会让玩家分不清"我是不是又走了一步"。

**② 回归**

```bash
npm test
```

`[27] 音频系统` 段会守住：素材非静音、cue 表字段完整、冷却生效、声部池不超上限、

**③ 素材体检**


开发者工具 → 预览 → 扫码。**必须真机**，因为：

- iOS 静音键（`obeyMuteSwitch`）只有真机能验；
- 切后台的 `operateAudio:fail:access denied` 只有真机能复现；
- 手机小喇叭的低频（`push` 的 55~85Hz）在电脑上听着正常，外放可能完全没声。

## 10. 调参速查

| 想改什么 | 改哪里 | 注意 |
| --- | --- | --- |
| 某个音效太吵 / 太轻 | `audio-cues.js` 的 `gain` | 只改相对关系；不要超过 1.0 |
| 连打时还是像机关枪 | `audio-cues.js` 的 `cooldown` | 加大到 80~120ms；超过 150ms 会"漏音" |
| 连打时声音被吃掉 | `audio-cues.js` 的 `voices` | 加到 3；每个声部都是一个音频实例 |
| UI 音太抢 | `AudioManager.busGain.ui` | 全局生效，比逐个改 gain 一致 |
| 音乐太吵 | `BgmConfig.defaultVolume` 或 `stateVolume` | 玩家存档里有旧值，改默认值不影响老玩家 |
| 想换素材 | 重跑 `tools/gen-sfx.py`，或替换 `audio/*.wav` | 换完必须同步改 `durMs`（声部占用计时） |
| 想加新音效 | ① `gen-sfx.py` 加 `build_xxx()` ② `CUES` 列表加一行 ③ `audio-cues.js` 加 cue ④ 调用处 `playCue('xxx')` | 四步缺一不可，漏第 ③ 步会 `[Audio] 未知音效` |
| 想加新 BGM 场景 | `BgmConfig.stateVolume` 加一档 | `setBgmState('xxx')` 即可，不用改引擎 |

## 11. 已知限制 / 后续路线

按优先级排：

1. **BGM 只有 16s**。这是主包体积换来的折中。玩家停留超过 5 分钟会听出重复。
   → 正式版建议 60~90s 授权曲或委托制作，走分包或 CDN，格式转 mp3。
2. **没有音效变体文件**。同一 cue 的音高变化靠 `playbackRate` 抖动，
   基础库 2.11.0 以下不支持，会退化成"完全一样的声音"。
   → 若要覆盖老基础库，给高频 cue（`slide`/`push`/`bump`）各出 2~3 个变体文件，在 `audio-cues.js` 里列 `variants`。
3. **没有独立音量设置页**。目前一个按钮同时控音效和音乐（`game.js` 的 `toggleSound()`）。
   引擎内部已经是两条总线，加设置页时直接调 `setSoundVolume` / `setMusicVolume` 即可，不用动引擎。
4. **没有音频资源加载进度**。BGM 689KB 在弱网首启可能晚到 1~2 秒。
   → 目前 `loop` 播放不受影响（到了就响），但如果以后换成大文件，需要加 `onCanplay` 提示。
5. **没有音乐层（adaptive music）**。推箱子其实很适合"剩余冰块少 → 加一层高频脉冲"的紧张感设计，
   但需要 2~3 条同步音轨，体积翻倍，暂不做。
6. **没有做响度标准化（LUFS）**。当前用的是 RMS + 峰值限幅，够用但不够严谨。
   → 若要上架对音频有要求的渠道，用 `ffmpeg -af loudnorm` 统一到 −16 LUFS（需要先装 ffmpeg）。
