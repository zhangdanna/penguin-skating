## 一、当前通关奖励（现状盘点）

### 1.1 一次通关最多叠三层奖励

结算入口在 `game.js:onWin()`，调用 `foodManager.calculateRewards()`：

```
最终奖励 = 基础奖励 + 连续通关奖励 + 时间奖励
```

| 层级 | 代码位置 | 规则 | 折算食物价值 |
|---|---|---|---|
| **① 基础奖励** | `calculateRewards()` | 星级几星就发几条鱼（1~3🐟） | 1 ~ 3 |
| **② 连续通关** | `getConsecutiveBonus()` | 3 连→1🐟；5 连→1🦐；10 连→1🦑；**50 连→1🐠** | 0 / 1 / 3 / 10 / **50** |
| **③ 时间奖励** | `getTimeBonus()` | 三档时间阈值，分别给 🐠(50) / 🦑(10) / 🐟(1) | 0 ~ **50** |

时间阈值不是固定值，会随关卡号**双重放大**：

```
难度系数 dm = 1 + (关卡号-1) × 0.3
难度倍率 tm = 1（1-3关） / 1.3（4-6关） / 1.6（7关以上）

金鱼线 = 5  × tm × dm   秒
鱿鱼线 = 10 × tm × dm   秒
鱼线   = 30 × tm × dm   秒
```

实际算出来是这样（前表为秒）：

| 关卡 | 金鱼线 | 鱿鱼线 | 鱼线 |
|---|---|---|---|
| 第 1 关 | 5.0 | 10.0 | 30.0 |
| 第 4 关 | 12.3 | 24.7 | 74.1 |
| 第 7 关 | 22.4 | 44.8 | 134.4 |
| 第 20 关 | 53.6 | 107.2 | 321.6 |
| 第 40 关 | 101.6 | 203.2 | 609.6 |
| 第 60 关 | 149.6 | 299.2 | 897.6 |

## 三、问题诊断

### P1｜中后期"时间奖励"几乎必发金鱼 → 单次通关净赚 16 倍

第 30 关（困难，消耗 3🐟）：金鱼线 77.6 秒。这关 par = 47 步，按每步 1.5~1.8 秒算，正常通关就是 70~85 秒 —— **一半以上概率直接拿 1🐠（价值 50）**。

> 单次净收益 ≈ 50 + 2（基础）− 3（消耗）= **+49**

### P2｜总通胀 18 倍，体力系统形同虚设

| 项目 | 数值 |
|---|---|
| 打通 60 关的支出 | 185 |
| 60 次通关奖励（按每次 ≈51 计） | ≈ 2700 |
| 成就奖励 | 395 |
| **总收入 / 总支出** | **≈ 18 倍** |

### P3｜食物上限根本没生效

`maxFood = 30` 只在**自然恢复**里判断，`addFood()` 完全不设上限。金鱼会无限堆积，`getTotalFood()` 可以涨到四位数 —— 体力、看广告换食物、复活消耗 10🐟 这些设计全部失去意义。

### P4｜成就可被"刷关"农场化（最严重）

| 成就 | 问题 |
|---|---|
| 滑冰大师「通关 100 次」 | **关卡只有 60 关**，这个成就永远无法达成 —— 死成就 |
| 小有所成 / 滑冰达人 | `totalWins` 统计的是**通关次数**不是**不同关卡数**，反复刷第 1 关就能拿 |
| 星光初现 / 星光璀璨 / 星河满天 | `totalStars` 每次通关都累加，重玩第 1 关拿 3 星 = 又加 3 星，34 次重玩即可拿满 |
| 完美主义（价值 100） | 判定条件是「**已通关**的关卡全 3 星」且至少 3 关 —— **通关前 3 关就能白拿 2 条金鱼** |
| 精准操作 / 操作大师 | 实际判定是「3 星」（步数 ≤ par），而 par = 最优步数 × 1.2，**几乎所有三星都算**，不是真的"标准步数" |
| 连胜传奇「50 连」 | 连击只要求 30 分钟内通关，刷第 1 关也算 |
| 收藏家 | 只看**当前库存**有没有 4 种食物，中后期必然满足 |
| 闪电企鹅 10 秒 / 光速传说 5 秒 | 关卡 par 是 22~47 步，**物理上不可能**，反向成为死成就 |

### P5｜通关奖励可以无限重刷

`onWin()` 每次都发奖励，不区分首通 / 重刷。配合 P1，重刷一关稳赚不亏。

## 四、改造方案（待确认）

### 4.1 通关奖励瘦身

**核心原则**：单次通关 ≈ 回本；一次性收益（首通、三星首通）才是主要来源。

| 项 | 条件 | 新奖励 | 频次 |
|---|---|---|---|
| 通关基础 | 每次通关 | 按难度 1 / 2 / 3🐟 | 每次 |
| 速度奖励 | 用时 ≤ `par × 2.2` 秒 | +1🐟 | 每次 |
| 首通奖励 | 首次通过该关 | +2🐟 | 每关一次 |
| 三星首通 | 首次 3 星通过该关 | +1🦐 | 每关一次 |
| 连击奖励 | 3 连 / 10 连 | +1🐟 / +1🦐 | 每次达标 |

变化点：
- **删掉金鱼档和鱿鱼档**，时间奖励最高只给 1🐟
- 时间阈值改为 **par × 2.2 秒**（跟着关卡步数走，而不是关卡号），不再线性放大
- 连击奖励上限从 50（金鱼）压到 10（虾），删掉 50 连档
- 首通 / 三星首通奖励**写入存档**（`level_N.rewarded`），重刷不再发

改造后单次收支：中等关 1+1=2 vs 成本 2（打平）；困难 2+1=3 vs 3（打平）；专家 3+1=4 vs 5（略亏）。
首通额外 +2、三星首通 +3，所以**推进新关是正收益，原地刷关是零收益** —— 这才是体力系统该有的形状。

### 4.3 「返回」→「退一步」

现状：底部第三个按钮是「返回」，一点就回主菜单，**本关已扣的食物白花**。而暂停面板里已经有「返回菜单」，所以底部这个按钮是重复的退出口。

改为「退一步」：

**实现要点**
1. 新增 `this.history = []`，移动成功时把**移动前的格子坐标快照**压栈
   ```js
   { penguin: { col, row }, stones: [{ col, row }, ...], moves }
   ```
   存格子坐标而不是像素，避开动画中间态。
2. 撤销：弹栈 → 企鹅/冰块瞬移回该格 → `isMoving = false` → 步数回退 → HUD / 结算同步
3. 成本：**2🐟 / 步**（复活要 10🐟，这个便宜很多，合理）
4. 食物不足 → 复用 `watchAdForFood()` 的看广告入口，而不是静默失败
5. 栈上限 30 步，防止无限回溯
6. 边界：
   - 步数为 0 → 按钮置灰
   - 掉洞 / 冰块入洞导致的失败 → **不允许退**（`undoMove` 只在 `gameState === 'playing'` 时可用）
   - 已通关 → 不允许
   - 撤销后本关标记 `undoUsed`，**不计入「精准操作 / 操作大师」成就**，防止用食物刷成就
7. 音效：滑动音 + 轻振动

**已采用口径：U1（步数一并回退）**
符合直觉，但用食物可以换星级 —— 因此用 `undoUsed` 标记把这条路径挡在「精准操作」成就之外。
